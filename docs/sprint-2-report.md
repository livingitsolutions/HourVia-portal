3. **Schema/relationships.** Eight Drizzle PostgreSQL tables covered global users, immutable provider mappings, sessions, organizations, memberships, invitations, audit events and idempotency. UUIDs, explicit states, timezone-aware timestamps, nonnegative row/aggregate versions, scoped uniqueness and composite foreign keys protected tenant references. Session identity/user pairing and invitation/audit/idempotency tenant relationships were constrained. Audit was immutable; its aggregate version replaced a mutable row version.

4. **RLS/role design.** All tables received ENABLE/FORCE RLS candidates. Separate nonprivileged NOLOGIN migration/runtime roles had no superuser or RLS bypass. Runtime owned no schema/table, had scoped SELECT only, no provider browsing, no DML/DDL/TRUNCATE/role grants and no automatic bootstrap bypass. PUBLIC schema/database CREATE, TEMPORARY and function execution were restricted. Helpers used fixed search paths and revoked public execution. Context validated the live user/session pair and active tenant membership. Settings remained a trusted-server boundary, not a substitute for authentication. Bootstrap and command-specific privileged operations remained unimplemented and inaccessible to runtime.

5. **Exactly-one-owner enforcement.** An immediate partial unique index enforced at most one active OWNER. Deferred triggers on organizations and memberships enforced at least one for active organizations at COMMIT. Membership mutations locked the organization and required serializable isolation; identity reparenting and inactive OWNER state were rejected. Provisioning and transfer protocols combined locks, version comparison, ordered demotion/promotion, audit and idempotency atomically. Real concurrency behavior remained unverified until disposable PostgreSQL execution.

6. **Transaction/COMMIT handling.** A connection-injected harness initialized no client. Only an acknowledged COMMIT command returned a success value. A returned ROLLBACK was never success; typed failures and exceptions aborted. Serialization/deadlock retries required acknowledged rollback, fresh authorization/work, stable keys and at most three attempts. Uncertain COMMIT discarded the connection, returned no success and prohibited automatic retry. Recovery required authoritative committed idempotency lookup or bounded reservation of the same key. Existing Sprint 1 ports were unchanged; no live adapter mapped these outcomes.
